# BGF10000 fan presets

This profile applies only to FA fans with model `BGF10000` and subtype `15`.
Other models and subtypes keep their existing behavior.

The Midea App uses a combination of the legacy mode and speed fields:

| Public preset | App name | Mode | Speed field |
| ------------- | -------- | ---- | ----------- |
| `normal`      | 普通     | 1    | Motor speed |
| `forest`      | 森林     | 4    | 1           |
| `beach`       | 海滩     | 4    | 2           |
| `countryside` | 田园     | 4    | 3           |
| `baby`        | 宝宝风   | 3    | 1           |
| `sleep_1`     | 睡眠1    | 3    | 2           |
| `sleep_2`     | 睡眠2    | 3    | 3           |
| `strong`      | 强劲     | 9    | 12          |

The mapping is based on device responses captured while selecting each App option.
Raw mode/speed response fixtures and command serialization are covered by tests.

Use `set_attribute("mode", "forest")` or `turn_on(mode="forest")` to select a
preset. Both send the mode and submode together in one command. A preset's
submode takes precedence over a simultaneous `fan_speed` argument.

In comfort/sleep submodes, the public `mode` reports the specific preset and
`fan_speed` is `None`: the wire speed field is not a motor speed in these modes.
An unrecognized submode reports an unknown mode instead of guessing.
When powered off, the public speed remains zero as for other FA devices.

Explicitly setting a positive speed returns to normal wind. A plain `turn_on()`
preserves the current preset. The default speed count is 12 for this profile;
the existing `speed_count` customization still overrides it.

This library change is the protocol counterpart to
[midea_ac_lan#1129](https://github.com/wuwentao/midea_ac_lan/pull/1129).
